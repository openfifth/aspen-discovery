#### Code Maintenance
- Add a `DatabaseTransaction` class providing `runInTransaction()`, so a group of writes can be committed or rolled back as one. Write methods that report failure by returning false are handled: the work is rolled back and the failure raised as an exception, so a caller cannot report success for a write that did not happen. ([DIS-2508](https://aspen-discovery.atlassian.net/browse/DIS-2508)) (*CZ*)

#### Events
##### Introduce database transactions
- Event registrations are now saved as a whole. If any part fails, nothing is kept, and the patron or member of staff is told the registration did not work instead of being shown a success message. Applies to patrons registering themselves and to staff registering patrons. ([DIS-2508](https://aspen-discovery.atlassian.net/browse/DIS-2508)) (*CZ*)
- Cancelling a registration is now all or nothing. A cancellation that fails part way through can no longer leave the registration in place without its attendee numbers. Applies to patrons cancelling their own registration and to staff cancelling on their behalf. ([DIS-2508](https://aspen-discovery.atlassian.net/browse/DIS-2508)) (*CZ*)
- Joining an event waiting list is now all or nothing, so a patron can no longer be queued for an event that is missing from their events list. ([DIS-2508](https://aspen-discovery.atlassian.net/browse/DIS-2508)) (*CZ*)
- Registration problems that were previously discarded are now written to the log with the underlying error. ([DIS-2508](https://aspen-discovery.atlassian.net/browse/DIS-2508)) (*CZ*)
